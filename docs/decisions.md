# 决策记录（balatro-remake）

## D1 技术栈：TypeScript + PixiJS + Vite + vitest（2026-10-13）
- 按任务默认栈。纯逻辑（src/core，零 DOM 依赖）与渲染严格分离，vitest 全量单测。
- 渲染用 PixiJS（WebGL，适合卡牌动画/粒子/屏震），Vite 构建。

## D2 RNG：确定性 PRNG，不追求与原版 bit 级一致（2026-10-13）
- sfc32 PRNG + xmur3 字符串播种；支持 fork(label) 派生子流，
  保证洗牌/开包/触发判定等子系统互不干扰且全程可复现。
- 验收「同 seed 同操作 → 同结果」指本引擎内部可复现。

## D3 命名策略：数据层暂用英文原名 + codename 字段（2026-10-13）
- 本地学习版数据用原版英文名便于逐条对账；每条内容带 codename，
  发布版由脚本一键替换为原创名称（版权红线，任务第 0 节）。
- 扑克牌型名（Flush 等）为通用术语，直接使用。

## D4 小丑效果建模：注册器 trigger × condition × action（2026-10-13）
- 禁止 150 个 if-else。每张小丑 = 注册记录 {trigger, condition, action}；
  计分管线在固定时机广播事件，注册器匹配执行。特殊机制（如 Blueprint 复制）
  用少量内置 handler 表达。

## D5 数据置信度分级（2026-10-13）
- 本机无游戏文件 → 阶段 A 用社区文档采集（balatrowiki.org 等）。
- 每条数值必须带 source（URL）与 confidence（wiki-多源一致 > wiki-单源 > 社区共识）。
- golden test 只锁置信度 ≥ wiki-单源 的条目；低置信度条目进 TODO 待升级验证。

## D6 计分管线：事件队列模型（2026-10-13）
- 出牌结算 = 有序事件流：打出的牌从左到右逐张进入「计分事件」，
  每个计分事件内：卡牌自身点数 → 卡牌版本（edition）→ 强化（enhancement）→
  小丑从左到右；全部计分事件结束后进入「手中计分」阶段（钢铁牌等）；
  最后 chips×mult 结算。隐藏细节待 fact-table 确认后修订。

## D7 独立实现纪律（2026-10-13，用户指令）
- 用户明确要求「一定要独立实现」。
- 本项目与并行会话的 balatro-clone/ 完全独立：不读取其代码与实现细节，
  引擎/内容/测试全部自主实现；数据采集由本项目的独立代理完成。
- 对方项目产物仅可由用户日后人工对照，不进入本项目的实现与验证链路。
